Why it looks like this

Amber, not blue or white

The single accent is amber. That is not decoration. Amber is the traditional instrument-panel colour because it degrades night vision far less than blue or white light. You drive this car at night, the screen sits in your peripheral vision, and a bright white or blue tile is the one that ruins your dark adaptation. Everything else on the screen is neutral so the amber means something: it marks the primary action.

Nine identical tiles instead of a fancy grid

The tempting design is a bento layout with one big hero tile and smaller supporting ones. I deliberately did not do that. In a moving vehicle, uniform target size and a predictable grid position beat visual variety - you learn "CarPlay is top left" as muscle memory and stop looking at the screen. Hierarchy comes from colour instead of size, which costs nothing ergonomically.

The left column is the part you actually read

Clock, date and speed are the only things you glance at while driving, so they get their own column, oversized, with tabular figures so the numbers do not jitter as they change. Everything that requires a deliberate stopped-car interaction lives on the right.

No animation, no wallpaper, no blur

The third-party launchers you tried are heavy because of live wallpapers, blur, widgets and animated transitions. On a quad A35 with 1.92 GB this is where the lag comes from. This design has one state change in the entire interface: a tile darkens while your finger is on it. That is the only feedback needed, and it costs nothing.

Manifest essentials

A launcher is an ordinary app with one special intent filter. The home activity needs android.intent.category.HOME and DEFAULT, plus launchMode="singleTask", stateNotNeeded="true", excludeFromRecents="true" and screenOrientation="landscape". Without stateNotNeeded a launcher can misbehave when the system restarts it under memory pressure, which on 1.92 GB will happen.

How speed works

The unit has no CAN bus, so there is no vehicle speed signal to read. Speed comes from GPS instead: LocationManager on GPS_PROVIDER, then Location.getSpeed() which returns metres per second, multiplied by 3.6 for km/h. Two details that matter in practice - GPS speed lags real speed by roughly a second, and it goes stale when you lose sky view. If no fix arrives for 5 seconds the display should drop to a dash rather than freeze on the last number, because a frozen speed is worse than no speed.

How the tiles launch

Each tile resolves a package at startup and caches the launch intent. If a package is missing or disabled the tile renders dimmed and does nothing, rather than crashing. That matters because we disabled 16 packages earlier, and you may disable more later.

Build and install

  1. Install the toolchain: JDK 17 and Android command line tools via Homebrew, then sdkmanager pulls platform 30 and build tools. Roughly 2 to 3 GB. Nothing is written outside the SDK directory and the project folder.
  2. Scaffold the project under projects/car-headunit/launcher/ with a Gradle wrapper.
  3. ./gradlew assembleDebug produces the APK.
  4. Re-enable wireless debugging on the unit, pair, then adb install -r.
  5. Press Home, pick the new launcher, choose Always only once you are happy with it.

Risk and the way back

The one real hazard: a crash loop. If a launcher is set as the default Home app and it crashes on startup, the screen has nothing to fall back to, and this car has no physical controls beyond the bezel. Three mitigations, all of which we will use. Keep app.carlab.carlauncher and the stock com.android.launcher3 installed throughout. Choose Just once rather than Always until it has run for a few days. And keep wireless debugging paired while testing, so adb is a recovery path rather than a trip to the installer.

Beyond that, the failure modes are mild. A missing app dims a tile instead of crashing. No location permission shows a dash instead of a speed. The launcher stores nothing, so uninstalling it leaves no trace and Android hands Home back to whichever launcher remains.

What I need you to define

Mark these up however you like and I will revise the mockup before any code exists.

  • Tile set and order. Nine slots. Are these the right nine, and is the grid position right for the ones you reach for while moving?
  • CarPlay or Android Auto as the primary tile. You use both. One tile that opens the mirroring app, or two separate tiles?
  • Speed units and size. km/h assumed. It is currently the largest element on screen after the clock, which is a deliberate choice you may disagree with.
  • Clock format. 12 hour shown. 24 hour reads faster at a glance and needs no AM and PM.
  • What the left column shows when parked. Speed reading zero is dead space. It could show the date larger, the current track, or nothing.
  • Wallpaper. Currently flat black, which is fastest and best at night. A photo is possible but costs memory on a 1.92 GB device.
